# 动态数据源使用文档

## 1. 功能介绍

动态数据源模块提供了以下功能：

- 支持多数据源配置
- 支持主从数据源配置
- 支持注解式数据源切换
- 支持线程级数据源上下文管理
- 支持数据源的动态添加和移除

## 2. 配置示例

### 2.1 基本配置

在 `application.yaml` 文件中添加以下配置：

```yaml
# MyBatis配置
wbw:
  mybatis:
    # 启用动态数据源
    dynamic-data-source-enabled: true
    # 动态数据源配置
    dynamic-datasource:
      # 默认数据源
      primary: master
      # 数据源配置
      datasources:
        # 主数据源
        master:
          url: jdbc:mysql://localhost:3306/master_db?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver
          # 连接池配置
          pool:
            minimum-idle: 5
            maximum-pool-size: 20
            connection-timeout: 30000
            idle-timeout: 600000
            max-lifetime: 1800000
        # 从数据源1
        slave1:
          url: jdbc:mysql://localhost:3306/slave_db1?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver
          pool:
            minimum-idle: 3
            maximum-pool-size: 10
        # 从数据源2
        slave2:
          url: jdbc:mysql://localhost:3306/slave_db2?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver
          pool:
            minimum-idle: 3
            maximum-pool-size: 10
      # 主从数据源配置
      master-slave:
        master: master
        slaves:
          - slave1
          - slave2
        # 负载均衡策略：round_robin（轮询）、random（随机）
        strategy: round_robin
        # 开启负载均衡
        load-balance: true
```

## 3. 使用示例

### 3.1 注解式数据源切换

在方法上使用 `@DataSource` 注解指定数据源：

```java
import com.wbw.mybatis.annotation.DataSource;

@Service
public class UserService {
    
    @Autowired
    private UserMapper userMapper;
    
    // 使用默认数据源（master）
    public User getUserById(Long id) {
        return userMapper.selectById(id);
    }
    
    // 使用指定数据源（slave1）
    @DataSource("slave1")
    public List<User> listUsers() {
        return userMapper.selectList(null);
    }
    
    // 在类级别指定数据源
    @Service
    @DataSource("slave2")
    public static class OrderService {
        
        @Autowired
        private OrderMapper orderMapper;
        
        // 继承类级别的数据源配置
        public List<Order> listOrders() {
            return orderMapper.selectList(null);
        }
        
        // 方法级别的注解会覆盖类级别的配置
        @DataSource("master")
        public void createOrder(Order order) {
            orderMapper.insert(order);
        }
    }
}
```

### 3.2 编程式数据源切换

使用 `DataSourceContextHolder` 手动切换数据源：

```java
import com.wbw.mybatis.datasource.DataSourceContextHolder;

@Service
public class ProductService {
    
    @Autowired
    private ProductMapper productMapper;
    
    public List<Product> getProductsFromDifferentDataSources() {
        List<Product> result = new ArrayList<>();
        
        try {
            // 使用 master 数据源
            DataSourceContextHolder.setDataSourceName("master");
            List<Product> masterProducts = productMapper.selectList(null);
            result.addAll(masterProducts);
            
            // 切换到 slave1 数据源
            DataSourceContextHolder.setDataSourceName("slave1");
            List<Product> slave1Products = productMapper.selectList(null);
            result.addAll(slave1Products);
            
            // 切换到 slave2 数据源
            DataSourceContextHolder.setDataSourceName("slave2");
            List<Product> slave2Products = productMapper.selectList(null);
            result.addAll(slave2Products);
        } finally {
            // 清除数据源上下文
            DataSourceContextHolder.clearDataSourceName();
        }
        
        return result;
    }
}
```

## 4. 注意事项

### 4.1 事务与数据源

- 数据源切换必须在事务开始之前执行
- 在事务内部切换数据源不会生效
- 建议将 `@DataSource` 注解放在 `@Transactional` 注解之前

### 4.2 性能考虑

- 频繁切换数据源会增加系统开销
- 建议在服务层统一管理数据源切换
- 对于只读操作，优先使用从数据源

### 4.3 异常处理

- 确保在 finally 块中清除数据源上下文
- 使用编程式切换时，必须手动清除数据源上下文

### 4.4 配置验证

- 确保配置的数据源名称在代码中正确使用
- 确保所有配置的数据源都能正常连接
- 建议在启动时验证数据源配置

## 5. 高级特性

### 5.1 动态数据源管理

可以通过 `DynamicDataSource` 实例动态管理数据源：

```java
import com.wbw.mybatis.datasource.DynamicDataSource;

@Service
public class DataSourceManagerService {
    
    @Autowired
    private DynamicDataSource dynamicDataSource;
    
    /**
     * 动态添加数据源
     */
    public void addDataSource(String name, DataSource dataSource) {
        dynamicDataSource.addDataSource(name, dataSource);
    }
    
    /**
     * 动态移除数据源
     */
    public void removeDataSource(String name) {
        dynamicDataSource.removeDataSource(name);
    }
}
```

### 5.2 主从数据源自动切换

配置主从数据源后，系统会自动在写操作时使用主数据源，读操作时使用从数据源。

### 5.3 数据源健康检查

建议结合 Spring Boot Actuator 实现数据源健康检查：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info
  health:
    db:
      enabled: true
```

## 6. 故障排查

### 6.1 常见问题

1. **数据源切换不生效**
   - 检查 `@DataSource` 注解是否正确使用
   - 检查是否在事务内部切换数据源
   - 检查数据源名称是否配置正确

2. **数据源连接失败**
   - 检查数据库连接信息是否正确
   - 检查数据库服务是否正常运行
   - 检查网络连接是否畅通

3. **事务异常**
   - 确保在同一事务中使用相同的数据源
   - 检查事务配置是否正确

### 6.2 日志配置

添加以下日志配置可以查看数据源切换情况：

```yaml
logging:
  level:
    com.wbw.mybatis.aspect.DataSourceAspect: debug
    com.wbw.mybatis.datasource: debug
```

## 8. 总结

动态数据源模块提供了灵活、强大的多数据源管理功能，支持多种使用场景：

- 读写分离
- 分库分表
- 多租户数据隔离
- 跨数据库操作

通过简单的配置和注解使用，可以轻松实现复杂的数据源管理需求。
