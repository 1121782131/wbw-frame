## 使用示例

### 业务需求分析示例

**输入**：
```
我需要设计一个电商系统的微服务架构，包含商品、订单、用户、支付等核心功能。
```

**输出**：
```
# 电商系统微服务架构设计方案

## 服务边界划分
- 商品服务：商品信息管理、库存管理
- 订单服务：订单创建、订单状态管理
- 用户服务：用户信息、认证授权
- 支付服务：支付处理、交易记录
- 物流服务：配送管理、物流跟踪

## 技术选型建议
- 语言：Java + Spring Boot
- 通信：RESTful API + 消息队列
- 数据存储：MySQL + Redis
- 服务注册：Nacos
- 配置中心：Apollo
- 监控：Prometheus + Grafana

## 关键设计要点
1. 订单服务与支付服务通过消息队列异步通信
2. 商品服务采用缓存策略提高查询性能
3. 所有服务集成分布式追踪系统
4. 实现完整的熔断、限流、降级机制
```

### 架构设计评估示例

**输入**：
```
评估我们当前的微服务架构，主要问题是服务间调用链路过长，响应时间不稳定。
```

**输出**：
```
# 微服务架构评估报告

## 问题分析
- 服务调用链路过长：平均调用深度达到5层
- 同步调用比例过高：80%的服务间通信采用同步方式
- 缺少有效的缓存策略：重复数据查询频繁

## 优化建议
1. 引入API网关，聚合相关服务调用
2. 增加异步通信比例，使用消息队列处理非实时需求
3. 实现多级缓存策略，减少数据库压力
4. 优化服务依赖关系，减少循环依赖
5. 引入服务网格，统一管理服务间通信

## 实施计划
- 第一阶段：引入API网关和缓存
- 第二阶段：优化通信模式
- 第三阶段：服务网格集成
```
