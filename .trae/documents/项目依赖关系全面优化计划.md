# 项目依赖关系全面优化计划

## 一、依赖分析结果

### 1. 现有依赖结构
- **根pom.xml**：统一管理了Spring Boot、Spring Cloud、Spring Cloud Alibaba等核心框架版本
- **模块依赖**：
  - wbw-common：基础工具模块（Lombok、Hutool、Commons Lang3、Guava、Jackson、Fastjson2）
  - wbw-security：安全模块（JWT、Spring Web、AOP）
  - wbw-web：Web模块（Spring Web、Validation、SpringDoc）
  - wbw-mybatis：MyBatis增强模块（MyBatis Plus、MySQL驱动）
  - wbw-redis：Redis模块（Spring Data Redis、Jedis）
  - wbw-nacos：Nacos模块（Nacos Discovery/Config、Resilience4j）
  - wbw-rocketmq：RocketMQ模块（RocketMQ Spring Boot Starter）
  - wbw-dubbo：Dubbo模块（Dubbo、Seata）
  - wbw-starter：空模块

### 2. 发现的问题

#### 2.1 冗余依赖
- wbw-common中同时引入了Jackson和Fastjson2，可能造成功能重叠
- 多个模块重复引入Lombok（虽然大多是provided或optional）
- wbw-common中引入了testng且作用域为compile，可能不合适

#### 2.2 版本管理问题
- 部分依赖（如Seata、Resilience4j）在子模块中直接指定版本，未在根pom中统一管理
- 版本更新不及时，可能存在安全漏洞风险

#### 2.3 依赖冲突风险
- 多个JSON库同时存在可能导致冲突
- 不同模块引入相同依赖但版本不一致的风险

#### 2.4 性能和体积问题
- Hutool-all包含所有模块，可能比按需引入体积大
- Guava库较大，需要评估必要性

## 二、优化计划

### 1. 依赖清理与精简
- **移除冗余依赖**：
  - 评估Jackson和Fastjson2的使用情况，保留一种主要JSON库
  - 移除wbw-common中不必要的testng依赖
  - 清理各模块中重复的Lombok依赖，统一在根pom中管理
- **按需引入依赖**：
  - 将Hutool-all替换为按需引入的具体模块
  - 评估Guava的使用情况，考虑用JDK自带工具类替代

### 2. 版本统一与管理
- **统一版本管理**：
  - 在根pom中添加Seata、Resilience4j等依赖的版本管理
  - 确保所有子模块使用统一的版本号
- **版本更新**：
  - 更新所有依赖到最新稳定版本
  - 特别关注存在安全漏洞的依赖

### 3. 依赖冲突解决
- **依赖树分析**：
  - 使用`mvn dependency:tree`分析依赖树，识别冲突
  - 解决版本冲突，确保依赖一致性
- **排除不必要的传递依赖**：
  - 对可能造成冲突的传递依赖进行适当排除

### 4. 性能与体积优化
- **依赖体积优化**：
  - 替换大体积依赖为轻量级替代方案
  - 移除未使用的依赖
- **性能优化**：
  - 选择性能更好的依赖版本
  - 评估并优化核心依赖的性能特性

### 5. 安全漏洞检查
- **漏洞扫描**：
  - 使用依赖扫描工具检查已知安全漏洞
  - 及时更新存在漏洞的依赖版本

### 6. 建立依赖管理规范
- **制定依赖引入标准**：
  - 明确依赖引入的审批流程
  - 建立依赖评估机制
- **定期更新机制**：
  - 制定依赖更新计划
  - 建立依赖版本监控机制
- **版本锁定策略**：
  - 实施依赖版本锁定，确保构建稳定性
  - 使用dependencyManagement统一管理版本

## 三、实施步骤

### 1. 准备阶段
- 对项目进行全面依赖分析
- 制定详细的优化方案
- 备份当前项目配置

### 2. 实施阶段
- 按照优化方案逐一执行依赖调整
- 执行依赖树分析，解决冲突
- 进行安全漏洞扫描和修复

### 3. 验证阶段
- 执行项目构建，确保无编译错误
- 运行单元测试，确保功能正常
- 进行性能测试，评估优化效果

### 4. 文档阶段
- 记录依赖优化过程和结果
- 更新项目依赖管理文档
- 制定后续依赖管理规范

## 四、预期效果

- **减少项目体积**：移除冗余依赖，按需引入
- **提升构建速度**：减少依赖数量和体积
- **降低安全风险**：更新存在漏洞的依赖
- **提高可维护性**：统一版本管理，建立规范
- **确保稳定性**：解决依赖冲突，锁定版本

通过以上优化措施，项目的依赖管理将更加规范、高效，为后续的开发和维护工作奠定良好基础。
